==============================================================================
1. INTRODUCTION                                          *pastel-introduction*

    pastel.vim previews the color under the cursor: move the cursor onto a
    color code, such as #FF8800, and a small popup shows that color, on the
    backgrounds of your choice. The popup goes away when the cursor leaves the
    code or you enter insert mode.

==============================================================================
2. REQUIREMENTS                                          *pastel-requirements*

    - Vim 8.1.1553 or newer, built with |+popupwin|, |+textprop| and |+eval|
    - A GUI, or a terminal with 'termguicolors' enabled

    Without these, the plugin does nothing, and does not raise errors.

==============================================================================
3. NOTATIONS                                                *pastel-notations*

    These color codes are recognized:

    - #RGB, #RRGGBB, #RGBA and #RRGGBBAA; the last also as #AARRGGBB, SEE
      |g:pastel_alpha_position|
    - rgb(), rgba(), hsl(), hsla(), hwb(), hwba(), hsv() and hsva(), in upper
      or lower case, in the comma notation, as in rgb(255, 0, 0, 0.5), and the
      space and slash one, as in rgb(255 0 0 / 50%); hwb() has no comma
      notation, as in CSS

    A hexadecimal code must not be preceded or followed by a letter, digit or
    underscore, so that eg. "#define" is not taken for a color. A function
    with a mistake, eg. a missing component, is ignored.

    A color with an alpha channel is shown blended over each background: on
    black it looks darker, on white lighter, and on the checkered background
    the checkers show through.

    Lines longer than 'synmaxcol' (0 means no limit) are not searched, as that
    would slow down moving the cursor in minified or machine-generated files.
    No color is previewed for a code in a closed fold, as it is not displayed
    there.

==============================================================================
4. OPTIONS                                                    *pastel-options*

    All options are global variables, set in your vimrc or at any time later
    with :let; a change takes effect the next time the popup is shown.

    A value that is not valid for its option, eg. a float or a list for a
    size, raises no error: a short warning is shown, once per value, and the
    default is used instead. Numbers may also be given as strings, eg. '6'.

    Except for g:pastel_color_mode and the four color options, which belong to
    the one shared popup, every option can be overridden for a buffer by the
    variable with the same name, b:pastel_<name>. It takes precedence over the
    global one in its buffer, is validated the same way, and an invalid value
    leaves the global one in effect, with a warning. Example: >
        autocmd FileType markdown let b:pastel_color_size=3
<

g:pastel_color_mode  (default "t")                       *g:pastel_color_mode*
    The previews to show and their layout: a string of block letters, left to
    right, with these meanings:

    - k: the color on black
    - w: the color on white
    - t: the color on a checkered "transparent" background
    - 2: the color on black and white, alternating, SEE |g:pastel_color_timer|
    - 3: the color on black, checkered and white, alternating, in that order
    - d: details, text about the color, SEE |g:pastel_detail_format|
    - .: separates what is on its two sides, SEE |g:pastel_detail_format|; it
      takes no room
    - a bar: the blocks after it go in a new row below

    Examples: >
        let g:pastel_color_mode = 't'     " one checkered block
        let g:pastel_color_mode = 'kw'    " black and white, side by side
        let g:pastel_color_mode = 't|kw'  " checkered, with both below
        let g:pastel_color_mode = 'td'    " checkered, with details beside it
<

    The text under the empty part of a layout, eg. right of a shorter row,
    stays visible. Any other value, or one in which the details are not valid,
    prints a warning; when set later, the previous layout stays.

g:pastel_detail_format  (default '%x')                *g:pastel_detail_format*
    What the detail regions, the d cells of |g:pastel_color_mode|, show: a
    template for the first region, or a list of them, one for each. A region
    with none shows its number and the color. A d is as large as a block, so
    'd' is just the text, 't|d' has it below a checkered block and 'td' beside
    it.

    Details in a row or column are one region, which must be a rectangle: 'dd'
    is one region of two cells. A . between cells keeps them apart, so 'd.d'
    is two regions, and a row of only . between rows does the same for the
    rows above and below it. Regions are numbered in reading order, by their
    first cell: in 'td|d.d' the d right of the t and the one below it are
    region 1.

    A region has as much room as its cells, in whole lines. If its text needs
    more, it takes it, to the right first, then down, if there is nothing
    there: not a block, another region, a . or a row of only . on the way. If
    it can not grow, a line that is too long is cut and ends in an ellipsis,
    and so does the last line if there are too many. All the regions grow to
    the right before any down, each in reading order. A line is broken where
    it may be, if it does not fit, instead of growing.

    A template is text with these items:

    - %r %g %b: the red, green and blue, 0 to 255
    - %a: the alpha, 0 to 1
    - %x %X: #rrggbb and, if the alpha is not 1, aa; lower, upper case
    - %t: the color code as written in the buffer
    - %{id}: the number of the region
    - %{rgb} %{hsl} %{hwb} %{hsv} %{cmyk}: the color as a whole
    - %{hsl.s}: one value of it, eg. the saturation
    - %#Group# %*: highlight the text after it with Group, until %*
    - %( %): text that is left out if an item in it is empty
    - %n: a line break
    - %N: where a line may be broken if it is too long; a space never is
    - %%: a %

    Numbers take modifiers after a colon, which can be combined: p is a
    percent (%r:p is 50%), P is that without the sign, f a fraction (0.5), x
    and X two hex digits, and .N is the number of decimals of the percent or
    the fraction (%r:p:.1 is 49.8%); o leaves out an alpha of 1, and a makes
    %x and the models always have it. A colon and a letter after an item are
    always a modifier; to have them as text, put the item in braces: %{r}:x.
    Example: >
        let g:pastel_color_mode = 'td'
        let g:pastel_detail_format = '%x%n%{hsl}%n%r:p %g:p %b:p'
<

    The models are shown in the CSS notation, hsl(32 100% 50%), with / 0.8
    after the values if the alpha is not 1, or with commas if asked for with
    c, hsla(32, 100%, 50%, 0.8). The values of the models are r g b of rgb, h
    s l of hsl, h s v of hsv, h w b of hwb and c m y k of cmyk, so %{hsl.s}
    and %{hsv.s} are not the same number; the hue is in degrees, the others
    percents (p, P and f change that), and the red, green and blue are as %r.
    Models are rounded to whole degrees and percents unless .N says otherwise,
    %{hsl:.3}; as every notation but cmyk, which has none in CSS and is not
    recognized as a color, is read by the plugin too, with enough decimals it
    is the same color. hwb has no comma notation.

    For %#Group# any highlight group can be used, one that does not exist is
    warned about once. These are defined as the color changes, if a format
    uses them: PastelRed, PastelGreen and PastelBlue have the color's red,
    green or blue alone as their background, PastelCyan, PastelMagenta and
    PastelYellow their inverses (255 minus it, in cyan, magenta or yellow),
    and PastelAlpha is a gray the lighter the less transparent the color is;
    the text is black or white, whichever is easier to read on it. Text
    without a highlight uses PastelDetail, which is linked to Normal, and can
    be changed. Example: > let g:pastel_detail_format = '%#PastelRed#%r%*
    %#PastelGreen#%g' <

    Everything not listed is reserved, as are the names of the other color
    spaces and notations, to be used later. An item that is not valid is not
    text: a warning says so and the default is used.

g:pastel_color_timer  (default 5)                       *g:pastel_color_timer*
    Seconds between the backgrounds of the 2 and 3 blocks changing, 0.1 or
    more. A smaller value turns alternating off.

g:pastel_color_size  (default 6)                         *g:pastel_color_size*
    Size of the color block, vertically in half-characters and horizontally in
    characters, so that it looks square. From 1 to 1000.

g:pastel_bg_size  (default 2)                               *g:pastel_bg_size*
    Size of the margin around the color block, in the same units, from 0 to
    1000.

g:pastel_alpha_position  (default "auto")            *g:pastel_alpha_position*
    Where the alpha is in 8-digit hexadecimal codes:

    - "last": #RRGGBBAA, as in CSS
    - "first": #AARRGGBB, as in Android
    - "auto": "first" in the filetypes of |g:pastel_alpha_first_filetypes|,
      "last" in the others, with a short note the first time an 8-digit code
      is found in a buffer

    The 4-digit form is always #RGBA.

b:pastel_alpha_position                              *b:pastel_alpha_position*
    If set, it takes precedence over |g:pastel_alpha_position| in its buffer.
    Example: >
        autocmd FileType cs let b:pastel_alpha_position = 'first'
<

                                              *g:pastel_alpha_first_filetypes*
g:pastel_alpha_first_filetypes  (default ['java', 'kotlin'])
    The filetypes where the "auto" of |g:pastel_alpha_position| means "first".

                                                   *g:pastel_ignore_filetypes*
g:pastel_ignore_filetypes  (default ['gitcommit', '*sql*'])
    The filetypes where no colors are looked for, as a list of glob patterns,
    eg. * for any characters, ? for one, [abc] for one of some and {a,b} for
    alternatives. Each is matched against the whole filetype, or any part of a
    compound one. The default is "gitcommit", where #123 is an issue and not a
    #RGB color, and sql and its variants, for their very long lines.

g:pastel_offset_x  (default 2)                             *g:pastel_offset_x*
    Horizontal placement of the popup relative to the color code, in
    characters: positive is right of the code, that many columns after its
    last column; negative is left of the code; 0 is centered on it.

g:pastel_offset_y  (default 0)                             *g:pastel_offset_y*
    Vertical placement relative to the cursor line, in lines: positive is
    below, negative is above, 0 is centered on the line.

    The popup does not cover the tabline, the status line of the last window
    or the command line. If it does not fit on the screen at the requested
    offset, the offset is inverted, eg. 2 becomes -2. With no room on either
    side of the code, the popup goes below the line, or above it. A popup
    larger than the screen is clipped, and a warning is shown once.

g:pastel_black_bg  (default "#000000")                     *g:pastel_black_bg*
    The color of the black background: #RRGGBB, or a color name Vim knows.

g:pastel_white_bg  (default "#FFFFFF")                     *g:pastel_white_bg*
    The color of the white background.

g:pastel_trans_fg  (default "#BFBFBF")                     *g:pastel_trans_fg*
    The light color of the checkered background.

g:pastel_trans_bg  (default "#404040")                     *g:pastel_trans_bg*
    The dark color of the checkered background.

==============================================================================
5. KNOWN ISSUES                                                *pastel-issues*

    - There is only one popup, shared by all windows and buffers, so its
      layout and colors (g:pastel_color_mode and the color options) are the
      same everywhere; and a popup is only shown for the cursor of the current
      window.
    - In Vims older than 8.2.0325, which lack the |SafeState| event, closing
      or opening a fold without moving the cursor leaves the popup as it was
      until the cursor moves.
    - In Vims older than 8.2.4713, which lack the |WinScrolled| event,
      scrolling the window without moving the cursor leaves the popup at its
      old position on the screen.
    - In Vims older than 8.1.1580, which lack |popup-mask|, the empty part of
      a layout, eg. right of the shorter row of 'wk|t', hides the text under
      it. A single row of blocks is not affected.
