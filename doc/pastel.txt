1. INTRODUCTION                                          *pastel-introduction*

    pastel.vim previews the color under the cursor: when the cursor is on a
    color code, such as #FF8800, a small popup shows that color, on the
    backgrounds of your choice. The idea is taken from the command-line tool
    sharkdp/pastel.

==============================================================================
2. REQUIREMENTS                                          *pastel-requirements*

    - Vim 8.1.1553 or newer, built with |+popupwin|, |+textprop| and |+eval|
    - A GUI, or a terminal with 'termguicolors' enabled
    - Neovim is not supported, as it has no popup windows

    Without these, the plugin does nothing, and does not raise errors. The
    parts that need newer versions are described in |pastel-issues|.

==============================================================================
3. USAGE                                                        *pastel-usage*

    Move the cursor onto a color code. A popup with the color appears next to
    the cursor, and disappears when the cursor leaves the code.

    The popup is hidden in insert mode, and when leaving the window or the
    buffer. It is shown again on leaving insert mode, or on entering a window
    whose cursor is on a color code. In Vims that have the |WinScrolled|
    event, it follows the code when the window is scrolled.

==============================================================================
4. NOTATIONS                                                *pastel-notations*

    These hexadecimal codes are recognized:

    - #RGB and #RRGGBB
    - #RGBA and #RRGGBBAA, or #AARRGGBB, SEE |g:pastel_alpha_position|

    #ARGB is not recognized: the 4-digit form is always #RGBA. The code must
    not be preceded or followed by a letter, digit or underscore, so that eg.
    "#define" or "#abcdefg1" are not taken for colors.

    These functions are recognized, in upper or lower case, in the comma
    notation, as in rgb(255, 0, 0, 0.5), and the space and slash one, as in
    rgb(255 0 0 / 50%), except where noted:

    - rgb() and rgba(), which are the same: the channels are numbers from 0 to
      255 or percentages, and may be mixed
    - hsl() and hsla(), which are the same: the hue is a number of degrees or
      an angle (deg, grad, rad, turn), the saturation and the lightness are
      percentages, or plain numbers of percents
    - hwb() and hwba(): the hue as in hsl(), the whiteness and the blackness
      as percentages, or plain numbers of percents; as in CSS, only in the
      space and slash notation. If they add up to 100% or more, the color is a
      gray
    - hsv() and hsva(), as in Less.js: the hue as in hsl(), the saturation and
      the value as percentages, or, as in Less, plain numbers from 0 to 1

    The alpha is a number from 0 to 1 or a percentage. Values out of range are
    limited to it, and a hue wraps around. The keyword "none" counts as 0, in
    the space and slash notation. A function with any other mistake, eg. a
    missing component, is ignored.

    A color with an alpha channel is shown blended over each background: on
    black it looks darker, on white lighter, and on the checkered background
    the checkers show through. Fully opaque colors look like their opaque
    form, and an alpha of 0 shows the background alone. The blending is done
    directly on the sRGB values. If a background color option is set to
    something other than a #RRGGBB color, the alpha is ignored for that
    background.

5. OPTIONS                                                    *pastel-options*

    All options are global variables, set in your vimrc or at any time later
    with :let; a change takes effect the next time the popup is shown.

g:pastel_color_mode  (default "k")                       *g:pastel_color_mode*
    The previews to show and their layout: a string of block letters, left to
    right, with these meanings:

    - k: the color on black
    - w: the color on white
    - t: the color on a checkered "transparent" background, as in
      sharkdp/pastel
    - 2: the color on black and white, alternating, SEE |g:pastel_color_timer|
    - 3: the color on black, checkered and white, alternating, in that order
    - a bar: the blocks after it go in a new row below

    Examples: >
        let g:pastel_color_mode = 't'     " one checkered block
        let g:pastel_color_mode = 'kw'    " black and white, side by side
        let g:pastel_color_mode = 't|kw'  " checkered, with both below
<

    Each block has its own margin, and all blocks are the same size. The area
    not covered by a block, eg. right of a shorter row, is transparent: the
    text under it stays visible. With odd sizes, the line where two rows meet
    shows the bottom of the upper block over the top of the lower one; a half
    line that has a block on one side and nothing on the other has the default
    color on the empty side.

    Any other value, including a leading, trailing or doubled bar, prints a
    warning. At startup the plugin does not load; when set later, the previous
    layout stays.

g:pastel_color_timer  (default 5)                       *g:pastel_color_timer*
    Seconds between the backgrounds of the 2 and 3 blocks changing, 0.1 or
    more, fractions allowed. A smaller value turns alternating off, showing
    the first background. The timer only runs while the popup is shown.

g:pastel_color_size  (default 6)                         *g:pastel_color_size*
    Size of the color block, vertically in half-characters and horizontally in
    characters, so that it looks square.

g:pastel_bg_size  (default 2)                               *g:pastel_bg_size*
    Size of the margin around the color block, in the same units.

    The sizes may be odd, in which case the color block starts or ends in the
    middle of a line. If the total height is odd, the lower half of the last
    line is left in the default color (Normal), as a line is always two half-
    characters high.

g:pastel_alpha_position  (default "auto")            *g:pastel_alpha_position*
    Where the alpha is in 8-digit hexadecimal codes:

    - "last": #RRGGBBAA, as in CSS
    - "first": #AARRGGBB, as in Android
    - "auto": "first" in the filetypes of |g:pastel_alpha_first_filetypes|,
      "last" in the others; as this is a guess, a short note ("pastel:
      assuming ...") is shown the first time an 8-digit code is found in a
      buffer

    The 4-digit form is not affected, as it is always #RGBA.

b:pastel_alpha_position                              *b:pastel_alpha_position*
    If set, it takes precedence over |g:pastel_alpha_position| in its buffer.
    Example: >
        autocmd FileType cs let b:pastel_alpha_position = 'first'
<

                                              *g:pastel_alpha_first_filetypes*
g:pastel_alpha_first_filetypes  (default ['java', 'kotlin'])
    The filetypes where the "auto" of |g:pastel_alpha_position| means "first".

g:pastel_offset_x  (default 2)                             *g:pastel_offset_x*
    Horizontal placement of the popup relative to the color code, in
    characters, SEE |pastel-placement|:

    - positive: right of the code, its left edge that many columns after the
      code's last column
    - negative: left of the code, its right edge that many columns before the
      code's first column
    - 0: centered on the code

g:pastel_offset_y  (default 0)                             *g:pastel_offset_y*
    Vertical placement relative to the cursor line, in lines:

    - positive: below, its top edge that many lines below the line
    - negative: above, its bottom edge that many lines above the line
    - 0: centered on the line

g:pastel_black_bg  (default "#000000")                     *g:pastel_black_bg*
    The color of the black background.

g:pastel_white_bg  (default "#FFFFFF")                     *g:pastel_white_bg*
    The color of the white background.

g:pastel_trans_fg  (default "#BFBFBF")                     *g:pastel_trans_fg*
    The light color of the checkered "transparent" background.

g:pastel_trans_bg  (default "#404040")                     *g:pastel_trans_bg*
    The dark color of the checkered "transparent" background.

g:pastel_detail_mode  (default "x")                     *g:pastel_detail_mode*
    Not in effect yet: nothing reads it.

==============================================================================
6. PLACEMENT                                                *pastel-placement*

    The popup is placed by |g:pastel_offset_x| and |g:pastel_offset_y|. If it
    does not fit on the screen at the requested offset, the offset is inverted
    along that axis, eg. 2 becomes -2.

    If there is no room on either side of the code, the popup is placed below
    the code's line instead, or above it if the vertical offset is negative or
    there is no room below; the vertical offset is used for the distance, or 1
    if it is 0. If it fits nowhere, it is moved onto the screen as far as
    possible.

    A popup larger than the screen is clipped, not wrapped, and a warning is
    shown once.

==============================================================================
7. KNOWN ISSUES                                                *pastel-issues*

    - In Vims older than 8.2.4713, which lack the |WinScrolled| event, the
      popup is only updated on cursor movement; scrolling the window without
      moving the cursor leaves the popup at its old position on the screen.
    - In Vims older than 8.1.1580, which lack |popup-mask|, the area of a
      layout that no block covers, eg. right of the shorter row of 'wk|t',
      hides the text under it, instead of being transparent. A single row of
      blocks is not affected.

==============================================================================
8. TESTS                                                        *pastel-tests*

    The tests are run from any directory with: >
        vim -Nu NONE -i NONE -es -S test/run.vim
<

    They print the failures, if any, and exit with an error status if there
    are any.
